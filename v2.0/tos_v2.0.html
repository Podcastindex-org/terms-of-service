We provide a free, open, categorized podcast index along with APIs and public data downloads so that developers, organizations, and hobbyists can build podcast experiences without having to do the heavy lifting of indexing and data management themselves.

3. What You Cannot Do

No proxying the API

You may not create a public-facing service that simply proxies, re-serves, or routes requests to the Podcast Index API. This includes, but is not limited to, building a public API, MCP server, or similar intermediary layer that passes traffic through to our infrastructure.

No scraping the API

You may not systematically crawl or scrape the API to pull bulk podcast or episode data - for example, sequentially walking through IDs or paging through all results. The API is designed for targeted, on-demand lookups in response to user activity, not for harvesting the full dataset. If scraping is detected, your credentials will be blocked.

Why? Our servers and bandwidth are funded by donations and the goodwill of our community. We happily serve individual developers and their apps directly, but we cannot absorb the load of bulk scraping or someone else's entire user base funneled through a proxy layer.

What you can do instead: If you want the full dataset, download it. We make this easy - our full feed catalog is published weekly as a SQLite database, and numerous other data exports are available at podcastindex.org/datasets. You are free to build your own podcast index from this data and run your own public API from it.

4. Identifying Yourself

Access to the API requires registering for credentials (an API key and secret). Keep these confidential. Do not share them publicly or embed them in client-side code or open-source repositories. If you believe your credentials have been compromised, contact us and we will issue new ones.

We do not allow developer registrations from free email services (e.g. gmail.com) due to a history of abuse from those providers. Please register with an email address tied to your project or organization.

All API requests must include a User-Agent string that specifically identifies your application. Generic or default library user-agents (e.g. axios, curl, wget, GuzzleHttp, python-requests) do not tell us who the traffic belongs to and will be rate-limited or blocked. Impersonating a web browser (e.g. sending a Chrome or Firefox user-agent) or an application you are not the developer of is also prohibited. Set your User-Agent to something like MyCoolPodcastApp/1.0 -your own app name, honestly represented.
